# unknown-signal

인류가 사라진 먼 미래, 외계 문명이 오래된 인간의 컴퓨터 기술로 지구에 신호를 보내는 실험적인 웹페이지입니다.

## 실행

별도 설치나 빌드 없이 `index.html`을 브라우저로 열면 됩니다. 로컬 서버를 사용하려면 저장소 폴더에서 실행하세요.

```sh
python3 -m http.server 8000
```

브라우저에서 http://localhost:8000 에 접속합니다. 같은 네트워크의 모바일에서는 컴퓨터 IP의 8000번 포트에 접속할 수 있습니다. 새로고침하면 부팅이 다시 시작됩니다.

## 파일 구조

- `index.html`: 터미널, 커서, 접근 버튼 및 접근성 안내
- `style.css`: 검정 배경, 작은 회백색 글자, 반응형 여백 및 커서 깜빡임
- `script.js`: 시스템 메시지, 출력 속도와 멈춤, 버튼 동작

## 첫 번째 단계

처음 1–2초간 커서만 표시하고, 이후 메시지를 한 글자씩 출력합니다. 정상 점검은 빠르게, 문자 해독과 재시도는 느리게 진행하며 중간에 멈춥니다. 부팅은 대략 25–35초 걸립니다. 출력이 끝나면 사각형 버튼이 나타나고, 누르면 `SIGNAL ACCESS REQUESTED`를 출력합니다. 요청은 한 번만 처리합니다. 사진 열람과 외부 통신은 구현하지 않았습니다.

마지막 `AWAITING INPUT_`의 밑줄은 실제 깜빡이는 커서입니다. 커서는 출력 뒤에 계속 유지됩니다. 운영체제의 동작 줄이기 설정에서는 커서를 고정하고 메시지를 줄 단위로 표시합니다. 스크린 리더에는 부팅 완료 후 전체 메시지를 알리며, 버튼은 Tab 및 Enter/Space로 조작할 수 있습니다.

## 검증

Chromium + Playwright에서 데스크톱(1440×900), 모바일(390×844, 320×568)을 검증했습니다. 가상 시계로 초기 대기, 점진적 출력, 전체 메시지의 정확한 일치, 부팅 후 버튼 표시, 클릭/키보드 요청, 가로 넘침 없음, JavaScript 오류 없음을 확인했습니다. 동작 줄이기 설정의 전체 메시지와 고정 커서도 통과했습니다. 데스크톱 캡처에서 화면 배치도 확인했습니다. `node --check script.js` 및 `git diff --check`가 통과했습니다. 실제 모바일 기기 및 Safari/Firefox는 검증하지 않았습니다.

## GitHub 반영

정적 파일만 사용하므로 의존성 설치가 필요 없습니다. 변경 파일을 검토한 뒤 커밋하고 작업 브랜치를 푸시하세요.

```sh
git add index.html style.css script.js README.md
git commit -m "Add DOS-style signal boot screen"
git push -u origin HEAD
```

GitHub Pages로 배포하려면 저장소 Settings → Pages에서 배포할 브랜치와 루트 폴더(`/`)를 선택할 수 있습니다.

## 이미지 열람

부팅 완료 후 사각형 버튼을 누르면 이미지 열람 화면이 열립니다. 사진 또는 NEXT를 눌러 다음 사진으로 이동하고, 세 번째 사진 또는 RETURN을 누르면 부팅 완료 상태의 처음 화면으로 돌아옵니다. 다시 사각형 버튼을 누르면 첫 사진부터 열립니다. 외계 문자 테스트 문장은 처음 화면에 유지됩니다.

사진은 `images/scene-01.jpg`, `images/scene-02.jpg`, `images/scene-03.jpg`로 업로드하세요. 파일명은 대소문자를 구분합니다. 없는 파일이나 손상된 이미지에는 `IMAGE UNAVAILABLE`이 표시되며, 다음 사진 이동과 복귀는 계속 작동합니다. 이미지는 비율을 유지하며 화면에 맞게 표시되고 자동 재생이나 전환 효과는 없습니다.

이미지 열람 검증: Chromium + Playwright에서 1440×900, 390×844, 320×568 크기로 이미지가 없는 경우와 테스트용 가로/세로 이미지가 로드되는 경우를 확인했습니다. 부팅 전 뷰어 숨김, 부팅 후 진입, 3개 상태 번호, 사진/버튼 이동, 마지막 항목에서 복귀, 재진입, 외계 문자 문장 유지, 사진 비율, 가로 넘침 없음 및 JavaScript 실행 오류 없음이 통과했습니다. 실제 업로드할 사진과 실제 모바일 기기에서는 별도 확인이 필요합니다.

## 두 번째 기록 진입 회귀 검사

Python Playwright와 Chromium이 설치된 환경에서 로컬 서버를 실행한 뒤 다음으로 검증할 수 있습니다.

```sh
TEST_URL=http://127.0.0.1:8000 python3 tests/record_entry.py
```

검사는 부팅 → 첫 기록 세 장 → RETURN → 느린 외계 문자 출력 → 완료 700ms 후 ACCESS RECORD → 두 번째 기록 세 장 → RETURN 흐름을 확인합니다. 폰트 로드 실패/지연 시 일반 영어 메시지는 숨기며, 기록 접근 버튼은 계속 제공됩니다. 폰트 로드는 최대 5초 대기합니다.


## 두 번째 기록과 OS 언어 해석

ACCESS RECORD는 `images/scene-04.jpg`(수영장), `scene-05.jpg`(골든 리트리버), `scene-06.jpg`(폐놀이터)를 순서대로 엽니다. 상태는 ARCHIVE : 01 / 03부터 03 / 03까지 표시됩니다. 두 번째 사진이 로드된 뒤 500ms 후 NEW FRIEND를 외계 문자로 타이핑하고, 이동하면 메시지를 지웁니다. 일반 영어 대체 문장은 표시하지 않습니다.

마지막 RETURN으로 메인에 복귀하면 1초간 기존 화면을 유지한 뒤, 영어 진단 문장을 같은 순서와 의미로 지우고 외계 문자로 다시 타이핑합니다. 전체 변환은 약 12초이며 완료 화면을 유지합니다. 변환 중 재진입을 막고, 완료 후에는 첫/두 번째 기록을 다시 열 수 있습니다. 변환은 페이지당 한 번만 실행되고 새로고침 시 초기화됩니다. 동작 줄이기 설정에서는 글자 삭제 대신 줄 단위로 폰트를 변환합니다. 폰트 실패 시 영어 화면을 보존하고 다시 열람할 수 있습니다.

```sh
TEST_URL=http://127.0.0.1:8000 python3 tests/archive_language.py
```

1440×900, 390×844, 320×568에서 실제 사진의 순서/비율, 메시지 지연과 취소, 1초 대기, 점진적 언어 변환, 완료 후 재열람, 이미지/폰트 실패 처리를 검증합니다. 테스트용 이미지 응답을 사용하려면 MOCK_IMAGES=1을 추가합니다.

## OS 업데이트 감지 연출

두 번째 기록 이후 OS 언어 변환이 완료되면 2초 대기한 뒤, 기존 내용과 버튼 아래에 영어 메시지 다섯 줄을 추가로 타이핑합니다.

```text
NEW OS UPDATE DETECTED.
INITIALIZING UPDATE...
CHECKING UPDATE FILES...
FILES VERIFIED.
STARTING UPDATE...
```

기존 외계 문자와 버튼은 유지됩니다. 검사 문장 뒤에는 조금 긴 멈춤이 있으며, 필요한 경우에만 커서가 보이도록 부드럽게 스크롤합니다. 동작 줄이기 설정에서는 즉시 스크롤합니다. 마지막 문장 뒤에는 커서만 깜빡이며 실제 업데이트, 다운로드 또는 화면 이동은 수행하지 않습니다. 페이지를 새로고침하기 전까지 한 번만 실행되며, 기록을 다시 열어도 출력이 초기화되거나 중복되지 않습니다.

전체 흐름 검증:

```sh
TEST_URL=http://127.0.0.1:8000 python3 tests/os_update.py
```

Chromium의 데스크톱 및 모바일 너비 1440/390/320px에서 두 기록, 외계 문자 메시지, OS 언어 변환, 완료 후 2초 대기, 영어 문장 순서, 기존 내용 보존, 커서/스크롤, 재열람 시 중복 방지를 검증합니다.

## 배포 파일 버전과 업데이트 영역 복구

HTML과 JavaScript가 서로 다른 배포 버전으로 캐시되면, 이전 HTML에는 `#os-update` 영역이 없어 언어 변환 이후 업데이트 출력이 중단될 수 있습니다. 출력 시점에 영역과 하위 텍스트/커서 요소를 다시 확인하고 누락된 요소만 생성합니다. 기존 외계 문자와 버튼은 변경하지 않습니다. HTML은 `script.js?v=os-update-2`, `style.css?v=os-update-2`를 참조해 이전 무버전 파일 캐시와 구분합니다.

PR 병합 후 저장소 Actions에서 Pages 배포 완료를 확인하세요. 이미 열어 둔 공개 페이지에는 이전 코드가 남아 있을 수 있으므로 Chrome에서 강력 새로고침(Windows/Linux: Ctrl+Shift+R, macOS: Cmd+Shift+R)을 한 번 실행합니다. 개발자 도구 Network에서 `script.js?v=os-update-2` 요청을 확인할 수 있습니다. 이 버전 표시는 새 HTML이 로드됐는지 확인하는 방법이며, 배포 완료 여부 자체를 보장하지는 않습니다.

이전 HTML/최신 JavaScript 조합, 하위 출력 요소 누락, 구형 무버전 스크립트 캐시를 포함한 회귀 검사:

```sh
TEST_URL=http://127.0.0.1:8000 python3 tests/os_update_recovery.py
```

기존 전체 흐름과 2초 대기 검사는 `tests/os_update.py`로 계속 실행합니다. 공개 사이트의 실제 캐시 응답은 이 작업 환경의 접근 제한으로 직접 확인하지 못했습니다.
